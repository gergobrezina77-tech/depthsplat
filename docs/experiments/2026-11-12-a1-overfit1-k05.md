# A1 Experiment: Overfit 1 Scene, Fixed Views, Fixed Budget k=0.5

Date: 2026-11-12. Ticket: A1-13. Run: `outputs/approach1/overfit1_k05`.

## 1. Goal

Give the Approach 1 fine-tuning a much simpler task than `overfit5`, so the curves are clean and
we can see whether the pipeline can overfit at all. Same trainable part (`gaussian_head`, 56k
params), same loss (`L_full + L_prefix`, linear), same lr and grad clip.

## 2. Setup

| Setting | `overfit5` | `overfit1_k05` |
|---|---|---|
| Scenes | 5 | 1 (`41b80c5fb43019e5`) |
| Views | random context pair + targets per step | fixed: context `[122, 167]`, targets `[136, 145, 160]` |
| Budget in training | `k ~ U[0.01, 1]` | `k = 0.5` every step |
| Augmentation (random flip) | on | off |
| Batch size | 4 | 1 (copies of one fixed input add nothing) |
| Steps / val interval | 3000 / 250 | 3000 / 100 |

Targets are novel views (not the context views). Command: `bash scripts/a1_overfit1_k05.sh`.
Config only, no Python changes:

- `assets/evaluation_index_a1_overfit1.json` lists only this scene; the evaluation sampler skips
  all others. Upstream `dataset.overfit_to_scene` fails here, because it asserts that train and
  test keys are disjoint (`src/dataset/dataset_re10k.py:261`) and our subset has the same scenes
  in both.
- `dataset.train_times_per_scene=1000` keeps the persistent validation iterator alive, so
  `val/psnr@k` is logged for the whole run (the `overfit5` val curves stopped after step 999).
- Check: with `optimizer.lr=0`, validation gives exactly the frozen eval numbers (13.53 / 30.32 dB).

Runtime: 10 min for 3000 steps (~5 it/s), ~2.1 GB GPU memory.

Training curves (means over sixths of the run):

- `loss/total`: 0.0191 → 0.0132 → 0.0112 → 0.0105 → 0.0102 → 0.0101. Falls steadily, flattens
  in the last third while the OneCycle lr anneals to 0.
- `train/psnr_prefix` (k=0.5): 24.5 → 28.8 dB. Smooth, no budget jumps.
- `train/grad_norm`: 0.35 at step 0, then 0.01-0.06. Below the clip of 0.5, unlike `overfit5`
  (median 5.2), so updates are no longer all clipped to the same size.
- `train/psnr_full` has one early dip (26.8 dB at step 29), then rises monotonically.

## 4. Findings

- **The pipeline can overfit.** At the trained budget, PSNR rises from 13.53 to 28.81 dB
  (+15.3 dB), 3.8 dB below the full set. `overfit5` reached 21.83 dB on this scene.
- **The full set gets better, not worse:** 30.32 → 32.57 dB. In `overfit5` it lost 2.1 dB on
  this scene. With one fixed input the head can fit both renders at once.
- **The gain is specific to k=0.5.** `k=0.25` peaks at 17.08 dB (step 599) and then slowly
  falls; `k=0.1` and `k=0.05` end below `overfit5`, which trained on random budgets.
- **Gate G1b passes:** `loss/total` falls steadily, and `val/psnr@0.5` ends well above 21.83 dB
  and moves toward 30.32 dB.

## 5. How the Overfit Was Achieved

Frozen vs. step-3000 checkpoint, same scene and views. Figures and `stats.json`:
`outputs/approach1/analysis_overfit1_k05/`.

**Swap test** (PSNR dB / LPIPS @ k=0.5): render one model's Gaussians, cut by the other
model's opacity ranking.

| Parameters \ ranking | Frozen ranking | Tuned ranking |
|---|---|---|
| Frozen | 13.53 / 0.365 | 13.93 / 0.334 |
| Tuned | 15.26 / 0.295 | **28.81 / 0.100** |

Neither the new ranking alone (+0.4 dB) nor the new parameters alone (+1.7 dB) explain the gain.
The head learned a kept set **and** parameters tuned for exactly that set.

**Random cut vs. cut by opacity** (mean of 5 seeds, PSNR dB):

| `k` | Frozen, opacity | Frozen, random | Tuned, opacity | Tuned, random |
|---|---|---|---|---|
| 0.5 | 13.53 | 19.01 | **28.81** | 25.74 |
| 0.25 | 6.33 | 12.13 | 16.18 | 17.09 |

At k=0.5 the opacity cut now beats a random cut by 3.1 dB. In the frozen model and in `overfit5`,
the random cut won. At k=0.25 the random cut still wins.

**Gaussian statistics:**

| | Frozen | Tuned |
|---|---|---|
| Top-50% set shared with frozen | 100% | 82.9% |
| Kept share, view 0 / view 1 | 52% / 48% | 60% / 40% |
| Opacity > 0.9 / < 0.05 | 0.1% / 7.6% | 5.0% / 13.5% |
| Opacity mass in top 50% | 0.72 | 0.79 |
| Median size, all / kept / dropped | 0.0107 / 0.0108 / 0.0106 | 0.0210 / 0.0155 / 0.0320 |

Mechanism (from `maps_context.png` and `renders_target0.png`):

- **The ranking now avoids keeping the same region twice.** The frozen model keeps ceiling and
  floor in both views and drops the fireplace and mantel in view 0. After the cut that leaves a
  black fireplace and a black band below the ceiling. The tuned model drops most of ceiling and
  floor in view 1, which view 0 already covers, and keeps the fireplace and mantel in view 0
  instead. Only 17% of the kept slots changed, but they are the ones that close the holes.
- **Opacity is more two-sided** (more values near 0 and near 1), so the cut at the median
  separates two groups more cleanly.
- **Kept Gaussians grew 1.5x** (median). That is some hole filling, but less than `overfit5`
  (3x), and the k=0.5 render keeps detail (bricks, rug pattern). Dropped Gaussians grew 3x and
  are faint (mean opacity 0.17). Only `L_full` trains them, and in the full render they act as
  a soft fill, which fits the full-set gain (+2.25 dB).
- **Why only k=0.5 works:** the learned split sits at the median opacity. At k=0.25 the cut
  falls inside the kept group, which has no learned order.

## 6. Limits

- One scene, three fixed views: this is memorization, not generalization.
- The mechanism (choose which view covers each region) is a cross-view decision. It is learned
  here for one scene. Whether `gaussian_head` can do it for unseen scenes is open: its input
  features already mix both views, but its own receptive field is only 5x5 pixels.
